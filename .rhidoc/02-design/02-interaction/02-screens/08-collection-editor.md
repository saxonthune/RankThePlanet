# Collection Editor

The affordance inventory for the `CollectionEditor` surface — where a Collection's identity and its Review template are authored or edited. **The source of truth is the rhidoc sidecar `08-collection-editor.inventory.json`** ([[00-index]], doc02.02.02.00 explains the shape); this `.md` is a lean companion.

The surface has three regions. The **topBar** carries *Cancel* (`CLOSE`), which discards uncommitted changes, and *Finish editing* (`DONE`), which commits and continues into `CollectionDetail`. When the editor is reached with `return-to-draft-context` set — the entry from [[11-add-location-to-collection]] (doc02.02.02.11) `TAP_NEW_COLLECTION`, where the in-flight candidate Location is carried as payload on `return-to-draft-context` — the same Save affordance fires `DONE_AS_DRAFT_RETURN` instead. The host pops back to `MapOverview`, commits the candidate against the just-created Collection (`Location.addToCollection`), and surfaces the same post-add Snackbar as `AddLocationToCollection`'s `PICK_COLLECTION`. The two events name the same button — the schema permits one transition per event, so the alternate target gets its own event id. The **metadata** region edits the Collection's `name`, `description`, `appearance`, and the `powerRanking` toggle (`Collection.edit`) — this is the only place that metadata is editable; `CollectionDetail` shows it read-only ([[02-collection-detail]], doc02.02.02.02). When the `powerRanking` switch is on, the Collection's entries carry a user-controlled rank position; the toggle itself lives on the Collection rather than on any one Review field ([[03-concepts]], doc01.03 §1, §3). The **template** region authors the Review template: *Adopt a built-in template* (`Review.useBuiltIn`) seeds the field set, *Add a template field* and the per-field *Edit, reorder, or remove* affordance shape it (`Review.editTemplate`).

The template region iterates the template's ordered fields ([[03-concepts]], doc01.03 §3). The first row is the implicit **date** field — locked, with no edit, reorder, or remove affordance; it stands in for the form's head-of-form date that every Review captures. The user-authored rows that follow show each field's name, its `type` — `score`, `text`, `enum`, `boolean` — and its per-type configuration. A `score` field's configuration is a numeric range, a `step` granularity down to one decimal, and a *Display As* style (`number`, `stars`, `icon`, `slider`, `bar`) that governs presentation without changing the stored number — a star rating and a 0–10 numeric rating are one `score` type with different config. A `text` field is always multi-line; the editor exposes no single-/multi-line control. The empty state — a template with no user-authored fields — is a valid end state, though a Collection that keeps it leaves `ReviewForm` with only the date to fill ([[06-review-form]], doc02.02.02.06).

A field's `name` (machine key) is derived from its user-facing label at create time and is immutable once defined ([[03-concepts]], doc01.03 §3). The editor does not surface the machine key as an input — the user types only the field's section name, and the editor sluggifies it. The per-field editor lets the user change `label`, `type`, and `config`; reordering and removal stay available on every user-authored field. There is no required toggle — fields are never required ([[03-concepts]], doc01.03 §3).

The per-field editor sheet carries three actions at the bottom. *Cancel* discards the edit. *Done* commits it and closes the sheet. *Add another* commits the current edit and re-opens the sheet on a fresh blank field, so a user authoring several fields in a row does not have to dismiss and reopen between each.

`Collection.create` and `Review.defineTemplate` are **deferred**: they are the create-mode counterparts of `Collection.edit` and `Review.editTemplate`, reached through the same metadata and template affordances when the surface opens for a new Collection rather than an existing one. They carry no distinct affordance, so the sidecar lists them in `deferred` and the `screen-inventory` verifier ([[05-verification-system]], doc01.04.02) counts them as acknowledged gaps. Nothing here names a Composable or a UiState; that binding is not part of the interaction layer (doc02.02.00).
